# Harsha writing style (outline → draft)

## Always do this first
1. Before any prose draft, produce a **nested outline** (bullets + indents) the user can review and edit.
2. Write the outline in the same thinking style as the final piece: conclusion-first points, one idea per bullet, concrete evidence noted under each point.
3. Do **not** write the full draft until the user reviews/edits the outline (unless they explicitly say to draft immediately).
4. After outline approval, write the draft following the rules below.
5. Before sending any draft, run an unslop pass (patterns below) and a hyphen/em dash scan.

## Prose rules (final draft)
- **Minto Pyramid Principle:** lead with the conclusion / governing idea, then supporting statements.
- Every paragraph (and major bullet in the outline) starts with a **meaningful conclusion sentence**, never an empty label (“Starting point”, “Her progression is clear”, “In conclusion”).
- **One idea per sentence.** Do not pack multiple ideas into one sentence with stacked clauses.
- Keep **normal paragraph grouping** in the draft (not one sentence per line).
- Tone: proper recommender / professional writing that stays human — not slangy/too casual, not template-speak, not overly polished AI voice.
- **No unexplained internal names or shorthand.** The audience has no company context. Explain once in plain language on first use.
- Prefer concrete evidence (problem → what others did → what the candidate did → impact) over adjectives.
- When the user pastes their own wording and asks for grammar only: correct grammar only; do not rewrite voice or content.
- Match any required structure/word counts from the source form or brief.
- Avoid jargon the user has rejected; use plain specifics instead.

## Punctuation (Harsha + unslop)
- **Avoid hyphens** in prose where a rewrite works (prefer open compounds or rephrase). Do not use hyphens as dash substitutes.
- **No em dashes, en dashes, or `--` used parenthetically.** Use periods or commas only. If a thought needs separation, end the sentence or use a comma. Do not swap in parentheses as a dodge.
- Avoid colon-as-mid-sentence connector. Colons are fine before a real list or example.

## Unslop patterns to cut (from Cursor `unslop` skill)
Content:
- Superficial -ing phrases: highlighting, ensuring, reflecting, showcasing, fostering (delete or make concrete)
- Vague attributions: “Experts believe”, “Industry reports suggest” (name the source or delete)

Language:
- AI vocabulary: Additionally, crucial, delve, enduring, enhance, fostering, garner, interplay, intricate, landscape (abstract), pivotal, showcase, tapestry, testament, underscore, vibrant
- Fancy “is”: serves as, stands as, boasts, features → is / has
- “Not just X, but Y” → state the point directly
- Forced rule of three → use the natural number of points
- Synonym cycling in one paragraph → pick one word and repeat it
- False ranges “from X to Y” when not a real scale → list directly

Style / artifacts:
- No boldface overuse; no inline-header lists that restate the line
- Sentence case headings; no decorative emojis; straight quotes not curly
- No chatbot phrases (“I hope this helps!”, “Certainly!”, “Great question!”)

Filler / plain speech:
- Cut “In order to” → “To”; “Due to the fact that” → “Because”; delete “It is important to note that”
- Cut excessive hedging
- No generic conclusions (“The future looks bright”)
- Cut abstract metaphor nouns (substrate, wedge, vector, north star, flywheel, scaffolding as metaphor, etc.)
- Say what it does or what happened, not how it feels
- Prefer active voice; cut weak adverbs or use a stronger verb / number
- Prefer plain words: use not utilize/leverage; help not facilitate; many not numerous; if not “in the event that”
- No mannered flourish where a literal phrase exists
- No over-compression: keep articles and full sentences

## Outline format
- Top-level bullets = section conclusions / governing ideas
- Indented bullets = supporting points, evidence, examples
- Note word-count targets and form beats under the relevant section when a form requires them
- Flag assumptions and missing facts in the outline before drafting
